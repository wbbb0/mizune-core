# 实例技能库

技能是实例共享、可版本化的方法说明。模型先浏览名称与适用场景，在任务需要时读取 `SKILL.md`，再决定如何使用已有工具。技能不增加工具权限；会话的工具边界、owner 身份、审批和工具自身限制仍独立生效。

## 内容与存储

库位于当前实例的 `dataDir/skills/`，不与其他实例共享。首次初始化写入内置技能，之后由用户或符合权限的模型维护。每个技能有稳定 ID、递增 revision、标准 `SKILL.md`、`references/` 文档和工具组绑定。已发布版本不可变，当前版本通过索引指向；管理 API 是读写入口，不直接修改落盘文件。

```markdown
---
name: web-research
description: 需要查证近期信息并提供来源时使用。
---

# 网页查证

先明确需要核实的问题，再搜索和阅读原始来源。
必要时读取 references/source-check.md 核对来源质量。
```

ID 和 frontmatter 的 `name` 均使用最多 64 字符的小写字母、数字和连字符，不能以连字符开头或结尾；名称在库中唯一。`description` 为 1–400 字符，正文必须包含中文说明；单份 `SKILL.md` 最多 64000 字符。不接受与其他技能仅空白或大小写不同的重复正文。

引用只接受 `references/` 下的 Markdown 相对路径，使用英文字母、数字、下划线、连字符、点和目录分隔符；禁止空目录段与 `.`、`..`。单个技能最多 30 份引用，总内容最多 256000 字符。短目录与正文只返回资源路径，资源内容通过 `read_skill_resource` 按需读取，避免把全部引用提前塞进上下文。

管理页首次只读摘要目录；选中技能才读当前正文和资源，版本历史另行读取，查看某一历史版本时再加载该版本全文。落盘布局包含版本内容、索引、会话草稿和任务版本快照；备份时应一起保留整个实例技能目录。

## 用户管理与模型维护

WebUI 的“技能”页可新增、编辑、禁用、锁定、暂停、删除、查看历史和回滚。工具组候选来自运行时目录，可用复选框多选。全局开关与预算在“配置 → 全局配置 → 实例技能库”中编辑，由配置 Schema 自动生成表单。

| 控制 | 效果 | 模型能否改变 |
| --- | --- | --- |
| 用户策略 `auto` | 可由任务按需选择，并非每轮自动加载 | 模型不能改变用户策略 |
| 用户策略 `disabled` | 禁止加载、读取引用和自主维护 | 只能由用户解除 |
| `modelEditable: false` | 用户锁定，保留加载能力，禁止模型自主修改和暂停/恢复 | 只能由用户解除 |
| `modelPaused: true` | 暂停加载与使用，必须附暂停原因 | owner 会话中的模型可按维护权限恢复；不能越过用户禁用或锁定 |

模型自主维护必须同时满足 `skills.enabled`、`skills.modelMaintenanceEnabled` 和 owner 身份。`save_skill` 提交完整正文、资源与绑定，必须写出具体 `changeReason`；`set_skill_paused` 必须说明暂停或恢复依据。模型不能通过这些工具解除用户禁用、修改用户锁，也没有技能删除工具。新增与修改不要求填满容量，发现重复或不再适用的方法应说明依据后调整或暂停。

owner 可在私聊或符合配置指令路由的群内 @ 机器人后使用：

```text
.config skill web-research
```

已有 ID 进入当前版本草稿；新 ID 新建草稿，省略 ID 时使用 `new-skill`。随后用自然语言要求模型修改正文、引用或绑定，先检查回显，再用 `.confirm` 发布，或 `.cancel` 丢弃。草稿在发布前不影响技能库；这是用户主动发起的配置流程，与普通对话中的模型自主维护区分。配置草稿仍受技能总开关与 owner 路由限制。切换资料配置前需先结束现有草稿。

保存、删除、确认草稿和回滚均校验基准 revision；并发修改返回 409，不覆盖新版本。WebUI 保留冲突草稿并要求重新读取。回滚创建新 revision，保留当前用户禁用与锁定策略；它不会让已开始的任务自动升级版本。

删除只提供给用户管理界面及受保护的用户 API，不向模型暴露删除工具。删除使技能离开有效索引并撤销旧任务对该生命周期版本的访问；同 ID 重建不会恢复旧任务资格。历史文件可能仍留在版本存储中，删除不承诺安全擦除磁盘内容。

通用文件工具提供应用内路径保护，阻止绕过专用技能接口。shell 仅向 owner 开放，并继承服务的操作系统权限，拥有该权限的人仍可直接操作磁盘；这属于应用内边界，不是物理隔离或独立文件系统安全域。

## 选择、绑定与按需加载

`skills.plannerSelectionEnabled` 独立于 `llm.turnPlanner.toolSelection`。开启时，Planner 可从短目录明确选择技能；关闭后，主模型仍可通过 `load_skill` 按需加载，工具需求触发的绑定技能补载也继续生效。

绑定表示“使用这些工具组时参考该方法”，不会授予工具组权限。以下信号可以触发绑定技能加载：Planner 在 `planned` 模式明确选择工具组、主模型显式申请被允许的工具组、即将实际执行需要这些工具组的工具。`toolSelection: all` 或某工具组已在可用全集中，本身不代表当前任务需要它，也不会因此加载全部绑定技能。

若模型已经发出实际工具调用，但相关绑定技能还未进入它上一次看到的上下文，运行时先加载技能并返回 `deferred: true, executed: false`。这次调用不执行实际动作；模型阅读方法、重新计划后再调用。技能工具只是方法入口，不会绕过原有工具权限检查。显式 `load_skill` 也应先于相关动作。

## 任务版本与恢复

任务开始时固定可选技能及版本目录，首次加载后记录实际 revision 与原因。相同任务的继续、工具续接、压缩后续接或停放恢复使用原固定版本；技能更新、新增或回滚留给新任务。任务快照独立于 transcript，进程重启后可恢复；保留当前与停放任务，并额外最多保留 16 个历史任务快照。

固定版本不等于永久授权。每次目录、加载、引用、上下文投影和会话观测都重新检查当前有效状态；禁用、暂停、删除或关闭总开关可使旧固定版本立即失效。同 ID 删除后重建也不能让旧任务继续读取旧生命周期内容。

Sessions 的“本任务技能”显示任务 ID、真正已加载的 revision、原因、估算 tokens 与拒绝原因，并随会话 SSE 的 ready/reset/status_patch 同步。可用目录不等于已加载；管理页显示最新版本，会话卡显示实际任务版本。会话卡只展示观测摘要，不包含技能正文和引用内容。

## 配置与预算

默认值与 `config/global.example.yml`、配置 Schema 一致：

```yaml
skills:
  enabled: true
  modelMaintenanceEnabled: true
  plannerSelectionEnabled: true
  maxCount: 40
  maxActiveSkills: 3
  maxBodyTokens: 4000
  maxResourceTokens: 4000
```

`maxCount` 为库数量上限（1–200），降额不自动删库，超额时禁止净新增；`maxActiveSkills` 为任务加载数量上限（1–10）。`maxBodyTokens` 是任务内已加载 `SKILL.md` 的估算总预算，包含 frontmatter；`maxResourceTokens` 是单次引用读取预算，两者范围均为 128–32000。预算不足时明确拒绝加载或读取，不静默截断文档。token 使用保守本地估算，并非模型供应商精确计费值。

关闭总开关后，不再提供技能目录、技能加载或模型技能工具；用户管理界面仍可维护存量库。关闭模型自主维护不会禁用技能使用，也不会替代用户发起的草稿确认流程。关闭 Planner 选择仅移除该选择职责，其他按需路径保留。

禁用、暂停、删除或关闭总开关后，可识别的技能加载、引用、补载和维护工具观察在下一次模型请求投影时替换为撤销提示，同时保留工具 call/result 配对。此机制不撤回已执行的外部动作，也不保证清除模型先前生成的自然语言、已有摘要或无法识别来源的历史文本。会话已加载清单会过滤失效技能，任务 pin 也不能绕过这些撤销检查。
