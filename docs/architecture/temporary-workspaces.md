# 临时工作区

工作区是一种可持久化的资源作用域。明确路径的文件操作仍通过原有 `LocalFileService`；临时任务先创建工作区，给相同的 filesystem 工具传 `workspace_id`。两种路径模式共用文件操作实现。

## 生命周期与存储

`TemporaryWorkspaceService` 维护工作区注册表，实例 `dataDir/temporary-workspaces/<id>/metadata.json` 保存名称、归属、创建时间、固定到期时间与状态，`files/` 保存可操作文件。工具无法经工作区路径修改元数据。

创建后固定 24 小时过期，不自动续期；重启加载元数据，不重置到期时间。启动扫描和每小时扫描删除过期文件，每次操作独立检查到期时间，因此回收延迟不延长使用期。工作区内操作与关闭/清扫按资源串行执行，避免清理与写入互相覆盖。关闭和到期记录短暂保留，原到期时间再过一天后删除记录。失败的清理会记录日志并在下次扫描重试。启动时同时清理未完成导入遗留的暂存目录。

文件跨重启保留，执行中的 Git 获取或导入不自动续传。未完成的暂存结果不会作为成功目录暴露。

## 工具与权限

`filesystemScope.ts` 为文件描述与处理器统一增加作用域，包含媒体查看及 `asset_export_to_filesystem`。传入工作区 ID 后，服务检查调用会话及用户归属，所有路径必须相对于工作区，不允许符号链接、特殊文件或越界路径。多路径操作使用同一工作区；根目录不能移动或删除。

作用域同时写回工具结果中的文件选择器和后续动作，保证分页、读取或发送不会意外回到默认文件目录。不传工作区 ID 时保留原有本地文件权限和路径语义；工作区不是对所有宿主机文件访问的全局沙箱。

资源列表工具按当前用户和会话过滤。WebUI 通过现有管理员认证访问工作区清单、目录、分页文本和文件内容接口，具有管理端全量可见性。

## 文件流转

用户消息附件、群文件与 URL 沿用现有下载/资产能力，取得资产引用后通过 `asset_export_to_filesystem` 复制进工作区。工作区修改不回写来源。`workspace_export` 或工作区模式的 `filesystem_send_to_chat` 复制登记资产，后续发送和会话预览不依赖临时文件存活。

`workspace_clone` 仅提供公开 HTTPS Git 快照：固定 Git 参数、清空宿主 Git 配置与凭据环境、限制 HTTPS 协议、固定解析得到的公网地址、禁止重定向、关闭 hooks/子模块并移除 `.git`。不提供 shell、解释器或项目脚本执行。Git 需要主机安装，单次最多两分钟。

`workspace_extract` 支持 ZIP，逐条检查原始路径与文件类型，以流式展开计数限制解压大小；在独立暂存目录完成后再移入工作区。`workspace_pack` 生成 ZIP，不覆盖已有目标。包及 Git 文件快照限制 256 MiB、10000 条目；不是系统级磁盘或内存配额。文本预览和编辑沿用 `maxPatchFileBytes`，每次最多预览 400 行。

## WebUI

工作区是资源清单的一类。详情使用现有 `ResponsiveSplitPane` 显示文件列表与预览，窄屏自动切换 Tab；选择文件切到预览，切回列表保留目录与选中项。文件切换采用请求代次检查，防止慢响应覆盖新选择。

文本按行分页，以纯文本渲染；图片、音视频使用受限的内容接口。未知格式提供下载。HTML/SVG 等不内联执行，内容接口设置 `nosniff`、沙箱 CSP 和非活动格式的附件响应，避免产生同源可执行页面。
