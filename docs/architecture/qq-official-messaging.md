# 腾讯官方 Bot 接入

## 范围与边界

`qqOfficial` 与 `onebot` 独立配置。修改官方连接配置后需重启进程，运行中的连接持有创建时的配置快照，避免身份与授权漂移。默认 `groupContext: mentions_only`，接收 `C2C_MESSAGE_CREATE`、`GROUP_AT_MESSAGE_CREATE`。设置 `groupContext: all_received` 后也接收 `GROUP_MESSAGE_CREATE`，需要在 QQ 客户端允许机器人接收群内所有消息。

专用群 @ 事件直接表明机器人被提及。全量事件只从顶层平台 mentions 判断：明确的 `is_you`，或与 READY 确认的机器人 ID 精确匹配；正文、引用中的 @、@全体和另一机器人的标记均不能激活回复。无法确认的普通消息仅保存上下文。群正文可能已被平台移除 @ 前缀。若正文仍含平台已确认的 `<@id>` / `<@!id>`，仅在根消息拆为结构化 mention，并从命令文本中移除，因此前置或后置 @ 都不妨碍 `。context` 等指令；引用内命令不会升级为根命令，owner 权限检查照常执行。

规范化入站消息位于 `services/messaging/incomingMessage.ts`；连接器位于 `services/qqOfficial`，统一投递入口为 `DeliveryCoordinator`。官方消息不伪造成 OneBot 事件。会话使用 `qq_official.<AppID>:p:<openid>`、`qq_official.<AppID>:g:<group_openid>`，平台消息引用保留字符串 ID 和连接维度。

## 回复授权

只有私聊或确认 @ 机器人的有效输入产生固定目标的运行时回复授权，随排队消息保留；不存入 transcript、不借用会话最新消息授权。文字和工具媒体共享序号与预算。官方群仅被动回复，过期或次数耗尽不自动降级主动消息。上传不直接发送。

官方指令回复不启用自动撤回；OneBot 继续在一分钟后自动撤回指令回复。手动 `.retract` 与自动撤回独立。

## 群上下文与引用内容

`all_received` 只收集平台实时推送的消息，不额外调用历史 REST 接口。当前没有已核实可用的官方群历史拉取接口，不能保证补齐停机期间未推送的消息。已存内容受统一会话保留、压缩及模型上下文预算限制。

普通群消息与 OneBot 共用媒体接收流程：图片和文件实时下载为本地资产，音频登记为本地引用，引用及嵌套转发中的媒体也递归导入。随后保存为独立用户记录，更新 Sessions 清单及实时流，不执行命令、初始化引导、媒体描述、语音转写或模型调用。明确 @ 触发回答时，统一 prompt 媒体准备流程按实际历史窗口处理已缓存的媒体。每个官方群会话按入站顺序处理，确保较早收到的上下文先落库。专用 @ 和全量事件使用连接、场景、目标及平台消息 ID 去重；先收到普通上下文再收到有效 @ 时，原记录保留 ID 和时间并升级，避免上下文重复。

共享远程媒体下载使用 `chatFiles.downloadTimeoutMs`（默认 15000 毫秒）的总截止时间，响应头与正文共用同一取消信号。失败或超时的入站媒体保存 `pending_media` 和私有来源引用，随后继续处理会话队列。触发回答时，仅对实际 prompt 窗口内的媒体补下载；来源仍有效时可在原消息位置恢复，并同步更新 WebUI。两端共用来源登记、重试与真实资产流程，详见 [消息引用与媒体恢复](message-media-recovery.md)。

消息接受的唯一权威是独立于聊天历史的 SQLite 接收记录，位于 state 数据库。准入通过后、执行任何媒体或命令操作前，原子接受消息或将上下文状态升级为已激活；同源后续事件拒绝重复执行。记录只保留来源标识、激活状态及过期时间，不含正文、身份权限或回复授权。记录保留 10 分钟（覆盖当前 5 分钟回复时效），最多 10000 条，容量用尽时拒绝接收，不驱逐仍有效记录。清空或重置会话不清除接收记录，重启也不会使 `.clear` 再次执行。处理失败的已接受消息不自动重放，以免重复执行结果未知的外部操作；这不保证消息处理恰好成功一次。

平台提供的 `msg_elements` 递归映射为 `embedded_message`，保留引用、聊天记录、并行消息、作者及索引；缺少正文时，先按平台 `msg_idx` 在当前会话可见历史及已缓存嵌套记录中精确查找；无缓存则只展示引用 ID，不伪造 OneBot forward ID 或借 OneBot 拉取内容。外层发送者始终是身份、权限和媒体导入的主体，引用作者只作为用户提供的资料进入模型上下文，不产生新消息角色或管理权限。

解析限制为 6 层、200 条嵌套消息、24000 字符及 16 个媒体，超限明确标记截断。持久化与 SSE 使用统一递归合同；运行时媒体 URL 入史前解析为本地资产或音频引用，导入失败则显示待恢复媒体标记，下载地址只进入私有资产数据库。WebUI 引用默认展开、聊天记录默认折叠，递归展示作者、索引、媒体与截断状态。诊断日志受 `logIncludeConversationContent` 显式控制，只记录有界内容及字段结构，排除事件授权值和附件下载 URL。此前仅保存类型说明的旧消息缺少下载地址，无法凭占位恢复媒体，需重新发送。

## 私聊流式

普通正文使用显式不可逆增量回调；开始提交后不再自动切换候选模型或重放协议恢复。结构化输出及实际启用原生搜索的候选需要最终验证和引用后处理，因此验证完成后投递。

线格式与腾讯官方 SDK 一致：`input_mode=replace`、`content_type=markdown`，每个分片携带已确认前缀与本次新增正文构成的完整快照；结束片重复最后完整快照并设 `input_state=10`，不发送空正文结束片。默认合并窗口 500ms，配置窗口不低于 300ms；收尾会立即冲刷待发正文。这与模拟人工延迟独立，不代表所有 HTTP 请求之间都有相同间隔。内部仍以增量缓冲管理未提交正文，取消不会截短已确认前缀。

原生文本流独立于 Web 草稿，串行提交正文分片并显式结束。插话使旧输出版本失效，只丢弃本地尚未提交的内容，保留已开始的工具计算。已提交请求成功表示平台接受，不表示客户端已经显示；网络超时可能产生结果未知，不能更换序号盲目重发。无法保证清除平台内部待下发正文。

## 会话发送节奏与身份

`pacingPreferences.outbound` 为会话级设置。创建时 OneBot 默认 `humanized`，Web、官方默认 `immediate`。这是出站模拟人工间隔，与输入 debounce、平台频控和流式合并相互独立。旧会话的设置经持久化结构迁移保留。

同一内部用户可明确绑定多个外部身份。身份反查必须指定连接，官方群成员和私聊默认隔离，不凭昵称或相同 ID 自动合并。官方管理者经已认证管理入口绑定，不能通过首条私聊自动取得管理权限。
