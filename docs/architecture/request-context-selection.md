# 请求历史与媒体准备

会话完整历史、运行历史与一次模型请求的上下文是不同的视图。请求窗口不能通过原生思考回放绕过，也不能通过媒体准备重新引入已排除的历史。

## 选择与协议投影

`SessionTranscriptStore` 先排除待插入消息组和本轮已单独传入的消息组，再调用 `selectRequestContext`。选择结果包含同一批 transcript 项、普通历史和逐项内容投影，使用当前路由预设的 `maxRecentMessages` 与 `maxImageReferences`。从最新引用向前分配图片额度，图片与表情共享历史额度；工具结果先按既有保留策略投影，再参与引用预算。

普通对话、设定、续写、定时与内部触发均将这个选择结果交给 provider projector。安全处理后的历史内容通过同一项身份映射进入回放，不能用原始 transcript 文本替换。参与者资料也只从选中的请求范围提取。完整记录和压缩边界不因请求裁剪而改变。

消息窗口按可见历史消息计数，不能按 provider 输出的消息条数裁剪。工具调用与全部结果组成完整交换；缺结果、重复结果和孤立结果不能进入原生回放。窗口之前的工具交换不会被单独补回。

未改写的原生思考、签名与 provider metadata 保留。原生载荷若覆盖多个响应片段，任何源片段越界或内容被安全处理、预算、恢复改写后，整个覆盖载荷失效，保留当前允许的普通内容。Google、OpenAI Responses 和 Anthropic 的原生载荷不能覆盖修改后的请求视图。签名块本身不做字符串裁剪或描述注入。

## 媒体准备

图片描述、音频转写、媒体恢复和本轮原生媒体输入共用一次准备期限，与主模型请求超时和每项派生任务超时分别归属。历史与当前输入分别准入；超额或超时的资源保留文字和句柄，提示尚未读取，不能编造描述。总期限不能在每个子阶段重新开始。

`llm.mediaPreparation.timeoutMs` 默认 30000；`maxCurrentMedia` 与 `maxHistoryMedia` 各默认 16，分别限制当前输入和已选历史中的自动准备资源总数，包含图片、表情、音频及待恢复文件。历史图片的引用次数仍受路由窗口约束，资源准入按身份去重。恢复前后使用同一份准入结果，不因句柄解析为 fileId 再取得一份额度。准备超时保留已通过安全检查的文字历史，只舍弃尚未准备或尚未审查的派生内容。

共享派生任务由请求租约和有限期限的后台租约持有。取消一个请求只解除它的租约；最后一个所有者离开时，排队项立即移除，运行项收到取消信号。实际任务退出之前仍占用并发槽；旧任务不得通过完成回调或存储写入覆盖同资源的新任务。队列与租约数量均有限，准入失败有明确原因。

会话阶段 `preparing_context` 显示“正在准备上下文与媒体”，表示 Planner 结束后、主模型请求之前的准备工作，仍属于可取消的生成状态。阶段更新经过 mutation epoch 校验；迟到准备结果不能修改新轮次阶段。WebUI 与会话 SSE 使用同一阶段语义。

本改动约束请求视图与准备工作，不代表已完成历史分页、冷存储卸载或应用全部关停治理。
