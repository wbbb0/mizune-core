# 消息引用与媒体恢复

## 职责边界

入站与引用工具共用 `services/messaging/importIncomingContent.ts`，图片、表情图片和文件统一交给 `MediaImportService`，音频继续由 AudioStore 登记。收到消息时下载文件；只有准备实际回答时才执行图片说明、识图和转写，不为普通群上下文调用模型。

来源登记位于 assets SQLite 的 `media_sources` 表，以连接和会话隔离。下载地址、原生定位器及来源上下文只保存在私有库；transcript、SSE、WebUI 和 prompt 只持有不透明的 `media_ref`。成功内容包含真实本地资产 ID，同时保留来源引用；失败内容使用 `pending_media`。表中每条来源保留 30 天，总量上限 50000，达到上限拒绝新登记，不驱逐有效来源。来源不是资产保留凭据，真实文件仍由现有资产引用和 GC 管理。

## 两端引用解析

OneBot 由 `OneBotReferenceResolver` 将 reply/forward 展开为公共 `embedded_message` 树，递归图片带原生消息或转发节点定位器。请求受深度、节点、字符、图片数量和总查询预算限制，无法取得的部分保留原生引用，超限部分标明截断。合并转发不再返回假图片 ID；`view_message` 和 `view_forward_record` 返回统一 contentParts、真实资产与附件信息；内层转发仍以按需查看入口返回。

OneBot 普通消息查询必须匹配当前群或私聊对端；私聊中机器人发出的消息还可通过本会话发送记录证明归属。模型引用工具只接受当前会话可见输入或可信引用工具结果中已出现的原生引用，不能凭猜测 ID 任意读取其他会话。用户实际分享的聊天记录保留原作者资料，但身份、权限与导入主体始终来自外层发送者。

腾讯官方接口没有本项目已核实可用的群历史拉取能力。仅展开平台实际推送的内联元素；裸引用按 `msg_idx` 在当前会话可见原消息及已缓存嵌套内容中查找。没有已收到的正文、URL 或本地记录时，保留引用占位，不能凭空补全。先前只有类型说明、没有来源的旧消息也需要重新发送。

## 模型按需读取转发记录

两端以及 Web 会话使用同一模型投影规则：`relation=forward` 的记录保留完整原树供持久化、GC 和 WebUI 查看；发给模型时只输出 `forward_record`、`record_ref`、消息数量和截断状态。普通引用仍保留其上下文，但引用内的转发也会折叠。WebUI 的人工展开不会自动给模型展开记录。

`view_forward_record({record_ref, offset?, limit?})` 只读取当前会话。默认返回 10 个内容片段，最多 20 个；文字和卡片摘要每段最多 1000 字，作者层级随片段保留，`nextOffset` 用于继续翻页。片段数不是原消息条数，长消息会占多个片段。嵌套转发仍返回独立的记录入口，需要再次调用工具。

缓存引用是记录内容的指纹，媒体部分以稳定的 `media_ref` 标识，因此补下载和资产更换不会使入口失效。指纹只用于寻址：每次调用仍从当前会话可见的用户消息或可信引用工具结果中找出真实记录；清空、排除或跨会话均不能凭旧入口读取。OneBot 尚未展开的原生来源使用明确的 `onebot_` 入口，只有该连接的真实可见引用才可请求平台；官方缓存入口不会被当成 OneBot 原生 ID。无需额外复制一份记录仓库。

折叠发生在入站图片描述调度、规划、安全投影、主模型媒体恢复及准备之前，并同步过滤隐藏记录的图片、文件和音频索引。历史压缩和用户重放也走相同的折叠格式，工具持久结果只保存已分页、已折叠的返回内容，避免重放把内层记录重新带入模型。

展开工具只返回正文与当前页的真实资产元数据，不发送图片二进制、不自动调用图片描述、识图或转写。图片继续在接收时缓存；工具读取时最多对本页的媒体补下载。模型应先阅读文字，再选择少量相关资产使用 `asset_media_view`（现有单次最多 5 个资产）或精读工具；不会因为展开含很多图片的记录就把整组图片送入 API。已有的接收解析深度、节点、媒体与字符上限继续生效，截断内容不伪造成完整记录。

## 补下载与退避

接收、引用工具和 prompt 恢复共用一个服务。相同作用域与来源引用的并发请求合并，下载并发最多 4 个。单次远程下载遵循 `chatFiles.downloadTimeoutMs`（默认 15 秒）；一次包含原生定位刷新和下载的恢复操作总截止时间为 30 秒。调用方取消等待不会取消其他调用方正在使用的共同下载。

失败状态持久化，退避从失败完成时开始，初次 30 秒，指数增加至最多 15 分钟。没有后台轮询或后台模型调用：后续实际回答或显式引用工具读取才会重试。OneBot URL 失效时，可按已绑定的原消息/转发节点定位器刷新一次；官方端只重试已收到的来源。再次收到同定位器的新 URL 会清除旧退避，旧请求的完成结果不能覆盖更新后的来源。已经成功但本地文件被删除的来源也可重新下载。

`recoverPromptMedia` 只检查实际历史窗口、重放消息和当前消息批次，单次最多恢复 16 个引用。历史图片预算同时覆盖待恢复图片，移出预算的引用不触发下载。`resolve_media_reference` 提供显式补下载入口，也必须通过当前会话可见内容授权和来源库的作用域校验。

## 原位更新与安全

恢复成功后，SessionManager 递归替换相同 media_ref 的内容，重新计算媒体列表、附件与 token 估算，并保存会话、发送 SSE patch。保持消息 ID、时间、分组与排除状态；已清空的消息不会因迟到下载重新出现。纯图片记录和普通消息使用相同的媒体字段更新，WebUI 无需刷新即可显示恢复后的图片。旧资产引用被移除，新的真实资产进入既有 GC 引用扫描。

新恢复或替换的资产必须重新经过 prompt 内容安全投影，然后才能进入 caption 或模型输入；相同资产的缓存命中不重复投影。URL 和平台授权字段不会通过恢复标记进入 prompt 或 WebUI。
