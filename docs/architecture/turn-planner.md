# 轮次规划与成本控制

轮次规划在主模型生成前完成必要的语义判断。它不必每轮调用，也不承担全部历史压缩职责。

## 职责边界与执行方式

- `turnPlannerPolicy.ts` 计算本轮所需职责和允许的回复选项。
- `turnPlanner/context.ts` 准备已折叠的消息、媒体描述及图片输入，不读取折叠的引用或转发正文。
- `turnPlanner/definitions.ts` 是问题与选项语义的唯一来源，定义中文判断条件、候选、阈值和答案映射。新增决策不另写一套普通模型提示词。
- `turnPlanner/chat.ts` 负责聊天模型调用和输出协议解析；`turnPlanner/decision.ts` 负责原生决策问题及有类型答案的映射。
- `llm/prompts/turn-planner.prompt.ts` 从问题定义生成普通模型的中文 prompt、JSON Schema 和输出额度估算，共用相同的可见证据格式。
- `turnPlanner/result.ts` 统一限制候选、技能数量、已有任务目标及回复/等待规则。展示理由不参与业务判断。
- `turnPlanner.ts` 协调选路、整个规划阶段的时间预算、取消和指标；`generationTurnPlanner.ts` 执行重入队、跳过回复与话题压缩等应用动作。

当前预设存在有效 `decision` 路由、模型声明相应用途且供应商实现该能力时，优先调用原生决策；否则使用 `turnPlanner` 聊天路由。该选择不根据模型名推断，也不要求决策模型同时支持聊天。只配置 decision、不配置聊天规划路由也可执行规划。`llm.decision.enabled` 仅控制 `make_decision` 工具可见性，内部规划仍遵守 `llm.turnPlanner.enabled` 和各职责的独立开关。要让某预设只使用聊天规划，显式将其 `decision` 设为空列表。

回复动作与模型档位是两个独立问题：回复动作使用 `reply / wait / no_reply`，档位使用 `small / large`。每个选项的 `description` 明确适用条件。话题切换、任务意图同样使用完整中文选项说明；恢复任务将意图与已有目标组合成同一选项，避免依赖前一个答案再次发请求。工具集、能力、上下文依赖、最近领域复用和技能使用逐候选判断；同一次原生请求的每个问题直接读取共同证据，不依赖其他问题的答案。技能最多选择三个，选择仍独立于工具集选择。超过原生接口 400 个问题或单题 255 个选项时，在调用前选择聊天规划。

原生决策采用保守的初始阈值：跳过回复、等待、切换话题和任务意图要求选择项概率与接口 confidence 均至少为 0.8；工具相关候选概率至少为 0.35，技能至少为 0.7。概率与 confidence 分别处理，不把普通模型的自报信心当作原生概率。阈值尚未通过真实业务语料校准，不代表已验证的准确率。拒答和未能确定的判断保留在 `undeterminedQuestions`；模型档位通过 `modelSelectionStatus` 区分已判定、未判定与本轮未请求。被拒绝的工具集候选保留可用，技能未判定不自动全部加载。不为拒绝或低置信度追加修复请求。

原生请求失败且仍有时间预算时，最多进入一次聊天规划链。整个过程（媒体准备、模型候选切换及降级）共享 `llm.turnPlanner.timeoutMs`；原生单候选还受 `llm.decision.timeoutMs` 限制。预算耗尽直接按原有失败策略继续回复，不新增完整超时窗口。调用方取消立即退出；媒体或上游无法及时取消时，其迟到结果不会继续触发模型请求或写入会话。

## 默认配置

```yaml
llm:
  turnPlanner:
    enabled: true
    toolSelection: all
    semanticWait: false
    maxWaitPasses: 1
    topicCompressionMinTokens: 2000
    topicCompressionMinMessages: 6
    supplementToolsets: true
    recentMessageCount: 6
    enableThinking: false
    timeoutMs: 20000
```

这些设置可在 WebUI 配置编辑器中修改。实例配置可以覆盖公共配置。

`toolSelection: all` 提供当前权限、模式、会话工具集偏好、模型能力允许的全部工具；不会解开权限边界。工具顺序遵循固定目录顺序。此模式不执行工具集选择、自动激活或语义补充，也不暴露 `list_available_toolsets`、`request_toolset` 及其提示。选模仍接收由工具操作语义生成的简短范围说明，不会因关闭工具选择而丢失操作边界。空的工具集边界仍代表没有业务工具。

`toolSelection: planned` 使用 planner 选择初始工具集，再执行确定性自动激活与可选语义补充；主模型可以申请一次额外工具集。`supplementToolsets` 仅在该模式生效。

`semanticWait: false` 依赖现有 debounce 合并连续消息，不进行语义等待判断。开启后允许模型判断半句话是否尚未结束，并受 `maxWaitPasses` 限制；达到次数上限便不再请求等待判断。关闭会减少前置调用，但较长停顿可能让主模型提前回应。

## 本轮职责计算

`turnPlannerPolicy.ts` 集中计算职责；无职责时直接继续生成，不调用规划模型，也不为 planner 准备图片描述或视觉输入。多项职责合并成一次请求。

| 职责 | 启用条件 |
| --- | --- |
| 模型选择 | 已配置完整模型候选且大小模型路由不等价 |
| 工具集选择 | `planned` 且有可选工具集 |
| 群聊回复判断 | 当前入口确实允许不回复；私聊、明确提及与结构化触发按现有强制回复规则处理 |
| 语义等待 | 开启且尚未达到等待上限 |
| 话题切换 | 历史压缩与 summarizer 可用，且待压缩历史满足两项门槛 |
| 任务意图 | 存在未结束的主任务或 parked task |

初始化/配置、显式跳过回复门控的续执行、定时任务和后台回调的独立生成入口，复用 `generationModelPlanner.ts` 做一次仅模型档位判断；回复门控、话题压缩、任务意图、工具与技能选择职责全部关闭。输入保留实际触发指令、已有任务摘要与历史摘要，避免只凭“继续”选成小模型；内容投影、原生/聊天适配、预算和取消仍走公共链路。等价路由或关闭 planner 时跳过该调用；档位未判定时优先选择可用完整模型。任务依据、状态和指标复用正常 `gate_decision` 记录。完整规划和仅选模入口共用任务证据投影：历史摘要、任务目标、下一步、障碍与停放摘要逐字段经过内容过滤，内部任务 ID、状态和结构保留，过滤不修改已保存任务；完整规划不重复投影已处理的历史和消息。进行中的工具循环不因此重复调用 planner。尚有待处理语音的批次沿用直接回复入口。所有模型驱动入口仍执行相同的操作档位校验，跳过前置规划不代表跳过执行边界。

普通私聊在等价模型、全量工具、无相关任务、历史较短的情况下无需调用 planner。群聊回复判断与任务暂停、取消、恢复等意图不会因全量工具而被关闭。

## 模型等价

比较有序候选链中的完整解析后模型配置：provider、实际 model ID、能力声明、API 参数均需一致；模型别名本身不参与比较。后备模型或顺序不同不视为等价。

等价时固定使用 `main_small` 路由，planner 不接收大小模型选择提示，也不输出大小模型选择字段；升级工具自动隐藏。相同 provider 与 model ID 但参数不同的配置仍可代表不同推理策略，因此保留选择能力。升级工具继续要求所有候选来自同一 provider、支持工具，并且当前位于小模型路由。

模型档位是 routing preset 的角色，不是程序测得的能力等级。大小候选链相同，或者 `mainLarge` 又回退到相同配置模型时，不能宣称实际能力已提升；配置加载会对等价路由或大小候选重叠发出明确提示；程序不会擅自替换或重排用户模型配置。

## 按操作影响选模

`llm/shared/modelSelectionPolicy.ts` 提供共用的档位条件；工具 descriptor 的 `modelPolicy` 声明操作性质，由公共策略结合参数及资源作用域计算实际调用的最低档位。工具可见或工具集已加载不代表本轮会执行其中的高影响操作。新增工具需同时声明语义，未声明不能自动视为低影响。

| 小模型适用范围 | 大模型适用范围 |
| --- | --- |
| 信息查询、公开网页阅读、范围明确的授权上下文读取 | 执行代码或命令、向交互程序输入操作、控制进程或运行环境 |
| 登记附件、受限临时工作区和当前任务产物处理 | 访问宿主机通用文件路径，包含读取、搜索、编辑及删除 |
| 明确对象内的用户事实、偏好、草稿和日常会话状态 | 改变权限、账号状态、长期执行规则、技能策略和有广泛影响的自动化 |
| 当前聊天的正常回复、发送任务产物和普通单次提醒 | 跨会话委派、对外提交或发布、信息披露及修改外部状态 |
| 常规表达与局部整理 | 复杂推理、多约束综合、冲突消解或精细质量控制 |

任一大模型条件成立则选 `large`。步骤多、输出长、工具多或暂缺外部事实不单独构成升级理由。普通数据持久化不自动升级。重复或开放式自动执行、修改已有自动化使用大模型；任务触发后仍按实际操作重新校验。

浏览器的 `click / type / press` 都可能产生外部影响，不能只识别提交动作或匹配按钮文案。明确读取与导航可用小模型；无法确认只用于查询的通用页面交互交给大模型核查。宿主机文件与临时工作区依据实际作用域区分，传了工具名或描述并不能绕过资源服务校验。

现有 `stateful_rp` 专用选模规则保留。本次不调整会话“允许模型自行升级”的开关语义，也不新增角色状态信号或后台分析调用。

## 执行前档位校验

每次模型工具调用在产生副作用之前检查最低档位。校验依据生成该批调用的真实模型来源与路由上下文，不只看最初的配置或已经更新的后续路由变量。

小模型提出需要完整模型的操作时，该操作暂不执行。若当前设置和候选允许升级，记录 `policy_upgrade`、将后续请求切到大模型，由大模型重新审视任务并提出调用；不会自动重放旧参数或重做已经成功的副作用。同批尚未执行的调用继续保留原模型来源，并发升级合并为一次路由变更。

没有可用大模型、会话设置不允许当前切换，或路由组合不受支持时，记录 `policy_unavailable` 并明确返回操作未执行，不静默让小模型执行。原有 `request_model_upgrade` 自主升级入口与开关保持现状。模型切换不扩大用户权限、会话工具边界或资源访问范围；取消、身份、模式和会话 epoch 仍在执行前检查。

## 话题压缩门槛

从真实 transcript 压缩快照取待压缩消息与工具观察，保留本轮批次。使用现有 token 估算权重计算原始内容大小，按其中 50% 估算可回收 token，给新摘要预留另一半；这只是触发启发式，并非实际压缩率保证。

同时满足以下条件才请求话题判断：

- 待压缩原始消息数达到 `topicCompressionMinMessages`。
- 预计可回收 token 达到 `topicCompressionMinTokens`。

已有摘要不计入门槛；压缩会移除旧原始历史，因此需要重新积累足够的新内容才会再次判断。未达到门槛时即使模型额外输出 `new_topic` 也不触发压缩。必要压缩由每个候选模型的完整请求预算独立决定：预算计算包含 system、工具、历史与输出预留，必要压缩失败时不会继续发起超预算请求。

## Prompt 与异常处理

两种执行方式共享问题定义和证据格式。静态指令在前，任务、历史、媒体和本轮消息在后。普通模型只输出生成的 JSON 协议，第一项必须是 `task_basis`，之后按定义顺序输出本轮需要的答案。该依据用一至两句概括可见任务要求、实际范围和关键约束，不预写决策结论、不编造未知事实、不展开完整解题；当前长度上限为 80 字，是实现初值而非经过准确率或延迟 benchmark 得出的最优参数。原生 Decision 不生成该字段，展示理由由结构化结果生成。

choice 答案使用合法候选值，predicate 使用布尔值，无法判定使用 `null`；普通模型无需伪造概率。Schema、prompt 与解析器来自同一份定义，未知字段、字段顺序错误、缺项、超长依据或非法候选都属于协议错误。等待只有明确未说完且通过本地文本及结构检查才会执行。回复动作与档位独立，不因等待或不回复被本地规则否决就覆盖模型档位。

视觉链最多使用五个已登记的可见媒体，优先本轮、再选近期历史，不支持视觉的聊天链使用既有描述服务；混合聊天候选链只有全部支持视觉时才直接传图。媒体仍经过公共访问及内容安全检查，动图复用抽帧处理，不直接向 Decisions 传入视频。

只有关闭思考、且整条候选链均为非思考模型或 provider 确实能关闭其思考时，才使用短输出额度。额度根据本轮问题、候选值和任务依据计算，不再假定固定 512 token 足够；通过各 provider 的输出上限字段传递。启用思考、不可关闭思考、原生 Gemini/Vertex 的思考模型，以及未声明思考控制映射的兼容供应商，均保留模型原有额度。隐藏思考文本不等于关闭思考，不能让短输出上限挤占推理额度。超时或不可解析结果不会新增修复请求；未判定项不能显示为已经确认的轻量档位，实际动作仍受执行校验。未启用职责的输出不会改变执行行为。

## 成本观测与 WebUI

- `turn_planner_required` 记录本轮职责与压缩候选估计。
- `turn_planner_skipped` 记录跳过原因；跳过规划不等于跳过主模型回复。
- `turn_planner_decided` 记录调用原因、输入/输出/缓存 token、总耗时、媒体准备耗时、模型耗时及媒体数量。
- 失败调用记录在 `turn_planner_llm_failed`；未取得 usage 的 token 为未知，不伪记为零。

实际规划决策的 `gate_decision` 包含 `plannerReasons` 和 `plannerMetrics`，并分别记录 `replyDecision`、`modelTier` 与 `modelSelectionStatus`。WebUI Sessions 详情显示普通模型的任务依据、未判定项、规划方式（原生决策/聊天模型）、实际规划模型、降级原因、调用职责、总耗时、媒体准备与模型耗时及 token。未判定档位显示为“未判定”，不能把保守采用的实际路由描述成模型已确认的结论。图片和表情输入分别计数。失败调用未取得 usage 时，包含该调用的总 token 保持未知，不能用降级成功请求的用量冒充整个阶段的用量。未请求话题判断时不记录话题结果；直接跳过 planner 的轮次不制造模型决策记录。

`model_route_event` 区分 `self_upgrade`、`policy_upgrade` 和 `policy_unavailable`。策略事件包含工具名、可取得的来源模型以及 `executed: false`；没有可用候选时保留空目标候选，不伪造供应商或宣称完整模型已经响应。Sessions 将其展示为自助升级、策略升级或无法升级，并明确操作尚未执行。

任务依据与这些事件均 `llmVisible: false`，不会进入主模型历史重放。`taskBasis` 属于内容性文本，仅按会话既有授权在 transcript、SSE 和 WebUI 中展示；默认内容日志过滤会移除它及其他自由文本，只保留受控状态码与指标。已有历史记录不补造依据。

媒体准备耗时包含等待或生成描述；描述服务自身的模型 token 不包含在规划模型 usage 中，需要结合描述服务日志评估。

固定工具清单有利于前缀复用，但不能保证缓存命中；动态 system 内容、历史重写、压缩、模型切换和服务端缓存策略仍有影响。缓存也不会消除工具占用的上下文长度。比较 `all` 与 `planned` 时，应同时测量整个轮次的费用、首字延迟、工具补充往返和任务成功率；本实现不预设节省百分比。

## 连接器能力与工具投影

`services/messaging/connectorCapabilities.ts` 根据真实会话身份和静态连接配置提供操作能力事实。会话来源决定账号、群与请求管理权限；本轮回复投递到 WebUI 不会把独立 Web 会话变成 OneBot 会话。媒体发送则同时考虑真实目标和资源类型，例如支持图片发送不代表支持普通文件发送。

工具 descriptor 声明所需能力，`tools/core/toolAvailability.ts` 组合能力、配置及用户权限。稳定缺失的能力不会进入模型工具目录或参数 schema；连接临时断开、额度不足和授权失效等运行状态不改变目录，执行时返回明确失败。执行入口重新检查当前边界，并且只允许收紧本轮工具快照。

可申请集合与本轮激活集合分别维护。`list_available_toolsets`、`request_toolset` 使用可申请集合，实际模型 schema 只包含已激活交集。空工具集隐藏；部分可用的工具集仅描述剩余操作。动态初始化工具也遵循该边界。初始化阶段的共享工具集同样尊重用户禁止；必需的初始化编辑工具仅由明确的 `setupToolsetOverrides` 声明优先提供，不通过通用工具集默认值绕过设置。资源句柄只提供当前可执行的能力与后续动作，发送操作还要求目标支持对应资源类型；未激活工具不能通过 `next_actions` 假装可直接调用。

WebUI 会话工具边界分别显示用户设置、当前会话允许状态和不可用原因。已知工具集的覆盖设置保存用户意图，即使连接暂不具备对应能力也不会删除该设置；覆盖不能强制打开缺失能力。未知工具集及非法设置由后端拒绝。该状态描述会话连接、配置和模式边界，实际调用仍按当轮用户权限检查，群会话不会凭空假定一个固定的操作者身份。

## 回复失败与取消

话题切换压缩属于优化，摘要服务失败时保留原历史继续准备，随后仍执行候选模型的完整请求预算检查；取消则立即退出，不把取消当作可降级故障。压缩在写回前检查取消信号与历史版本，避免迟到摘要覆盖新状态。

准备、生成和投递异常共享一次失败报告边界，先向内部 transcript 写入不可供模型读取的诊断，再尝试一次简短用户提示。提示投递失败不会递归重试，也不会重发原正文或工具；官方平台缺少回复授权、授权过期或额度耗尽时仅保留本地诊断。错误事件表示失败处理发生，实际送达仍以 assistant 消息为准。取消和已过期回复不发提示；释放本轮状态后继续处理下一条待办。
