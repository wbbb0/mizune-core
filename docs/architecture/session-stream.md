# Sessions 历史快照与 SSE 重同步

WebUI 用 REST 分页读取会话历史，以 SSE 接收在线追加、原位 patch 和状态变化。后端允许关闭超出队列预算的慢连接；关闭后必须重新取得权威视图，不能把断线前报告的总量当作已经收到的进度。

## 总量与接收进度

`ready.transcriptCount` 和 `transcript_item_added.totalCount` 都描述服务端总量。它们可能早于对应的历史项抵达浏览器，因此不能直接推进客户端接收进度。在线追加根据已收到的连续 `index` 推进进度；检测到索引缺口时重新同步，而不跳过中间项目。

每次首次选择会话、SSE 断开或 reset，客户端关闭旧连接，取消旧快照及分页请求，再通过 REST 取得末尾 25 项。新快照替换当前历史展示缓存；此前加载的更早页面重新按需读取，不把卸载缓存解释为删除会话历史。

## 快照到订阅的交接

新 SSE 从快照最早已加载的 `index` 开始重叠回放这一窗口，通常至多重复 25 项。重复 ID 按完整项目更新，不直接忽略，从而覆盖 REST 返回到订阅建立之间窗口内发生的原位变化。新追加继续通过同一流接收。后端既有的 epoch/reset 合同仍负责处理清空、恢复或索引重置。

任何断线重连都重取 REST 快照，包括服务端总量不变的情况，以恢复断线期间的旧项目 patch。REST 失败时明确清空失效历史及草稿展示缓存，从 SSE `transcriptCount=0` 重新同步；不会用旧总量跳过未接收数据。若服务仍不可用，后续重连继续遵守相同规则。

快照与分页请求携带 AbortSignal，并使用请求代次检查所有异步结果。切换会话、同一会话重新选择或 reload、取消选择和 reset 都会使旧结果失效；旧连接事件和旧分页结果不得恢复缓存或重新打开连接。

此规则提供末尾窗口的重取及交接一致性，没有新增 mutation cursor、永久变更日志或完整历史的增量存储协议。完整历史仍由 REST 分页和既有持久化负责；历史冷热分离及变更游标属于后续独立改造。
