# 跨会话上下文

跨会话参考使用已接收的聊天记录，不建立额外 agent，不对群聊逐消息调用模型、生成摘要或 embedding。未触发生成的监控消息仍由现有接收链路保存；本功能不为它们增加模型费用。真正回答时，参考窗口会增加主模型输入 tokens，因此有独立的总预算。

## 调度与时效

普通消息完成 debounce 后，在调用 turn planner 前启动关联会话的访问检查，与 planner 并行。planner 决定等待或不回答时，不构建跨会话 prompt，也不新增模型调用；等待结束重新进入生成时重新检查。访问检查有超时，超时或失败的来源不注入内容，截止时已经通过检查的来源仍可使用，不阻塞正常回答。检查只访问配置中的少量来源，不枚举所有会话。

权限检查的结果只是候选会话 ID。`GenerationPromptBuilder` 完成自身异步上下文准备后、组装最终 prompt 时，才通过同步回调读取这些会话的最新窗口。因此包含 planner、媒体准备和记忆检索期间已入库的消息。读取快照不会在模型请求中途改变；下一轮或显式工具查询才刷新。没有请求中途持续重启，也不会因为隔壁更新触发当前会话自动回复。

定时及 inline 生成复用同一读取服务；没有可确认的当前用户身份时不自动注入。初始化资料模式不自动注入。

## 读取模式

- `live`：当前保留的用户可见聊天，包括尚未回复的用户消息，以及已经成功发送的 bot 分段。未发送草稿、推理、工具执行结果、系统状态和已撤回记录不进入窗口。输入图片消息提供文本占位，不附带原图，不触发识图。首版共享文本聊天窗口，不共享通过工具发出的文件和图片；纯媒体输出不会推进完整文本回答快照。
- `last_completed_reply`：最后一次成功生成且发送队列排空后发布的聊天窗口。生成失败、发送失败或中断不推进发布快照；从未成功发布时返回 `available: false`，不回退到实时窗口。

“截至上次回答”指被参考会话的上次完整回答结束时已记录的聊天，不表示 bot 已经处理了该时刻之前的每条用户消息。生成期间到达、未被本轮消费的消息也可能在窗口中。它不是“当前会话上次读到的位置”。

发布窗口最多保留 32 条、约 4096 tokens 的序列化消息；每次返回仍受本次更小的预算限制。窗口独立保存到 `sessions.published_conversation_json`，随 session 持久化及手动存档读档恢复；历史压缩保留发布窗口，清空或撤回/截断涉及已发布窗口内的消息时使发布窗口失效，等待下一次成功回答重新发布。已有会话首次启用时没有历史发布快照。

不将当前 `historySummary` 附到旧快照，避免混入截止点之后的信息。`revision` 是内容版本摘要，消息 ID 确定末尾边界；时间戳只用于展示。`hasNewerMessages` 表示当前保留窗口末尾与发布边界不同，不代表完整未读计数。实时模式只能参考当前仍保留的原始记录，压缩移除的内容不会自动从长期摘要恢复。

## 配置

```yaml
conversation:
  crossConversation:
    enabled: true
    maxSources: 2
    maxTokens: 1500
    recentMessages: 12
    prepareTimeoutMs: 1000
    links:
      - targetSessionId: "qqbot:g:10001"
        sourceSessionId: "qqbot:g:10002"
        mode: live
```

`links` 是有方向的关联，上例只让 10001 参考 10002。ID 应从实际 Sessions 页取得；默认关闭且关联为空。配置数量超过 `maxSources` 时按配置顺序选择去重后的来源。`maxTokens` 包含参考说明、来源元数据和消息正文，使用本地估算而非供应商精确 tokenizer；不需要另一次模型调用。最新消息过长时截断并标注，按实际序列化元数据开销分配剩余预算，仍放不下正文时按配置顺序减少来源数，避免只注入空消息元数据。最多三处来源，避免以跨会话功能无限扩大每次输入。

## 权限与上下文边界

显式关联不绕过 `ConversationAccessService` 的请求者访问规则。Web 私聊按 participantRef 所属用户检查；OneBot 沿用自身私聊、NPC 私聊、群成员等现有策略。群聊目的地只能读取群聊来源，不能因提问者有私聊读取权限就把私聊带入群中。配置群到群关联意味着维护者选择了共享范围，仍需谨慎选择目的地受众。

参考消息以带来源的 JSON 置于独立参考说明中。它们不是本会话发言，也不是可执行指令。自动参考不会把外部聊天追加成当前 transcript 的用户消息，避免会话间相互复制。

## 工具与可观察性

`get_conversation_context` 支持 `mode: live | last_completed_reply`，默认实时，返回来源、内容版本、读取时间、是否有发布快照、是否存在更新以及截断标记。它与自动注入使用相同投影及读取函数，不返回源会话推理或工具细节。`search_accessible_conversations` 在群聊目的地也过滤私聊候选。

自动注入只存在于本轮 prompt，不改变 Sessions 聊天时间线；现有 prompt 调试快照的 systemMessages 可检查实际注入的来源、时间及内容。没有为参考来源伪造新的聊天气泡或额外 SSE 聊天事件。

## 验证

回归覆盖 planner 准备阶段后的新消息、预算、访问超时、取消、群聊与私聊边界、完成快照与实时视图差异、同时间戳消息、重启和压缩、撤回/清空、生成失败不发布，以及发送队列排空之前不发布。默认测试使用合成聊天和 mock 模型，不读取正式实例数据。
