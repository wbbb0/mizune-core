# 精选表情库

表情库按实例共享，使用 assets.sqlite 的 stickers 表。QQ 原有收藏仅作为按需导入来源，本地新增、修改、删除不写回 QQ，不依赖 NapCat 端可读的本地路径。默认开启，`stickers.maxCount` 默认 25（1–200）；关闭后隐藏工具，但不会删除收藏或解除素材回收保护。

## 资料与检索

每次新收藏先检查素材类型、计算 SHA-256 去重，再调用 `llm.imageInspector` 配置的视觉模型生成结构化资料。复用现有视觉预处理和内容安全检查，动图使用抽帧拼图。画面描述、可见文字属于观察；情景、情绪、风格、强度和注意事项属于使用建议，允许不确定性。使用心得独立维护。

同一已收藏内容不重复调用模型；同时分析同一内容合并请求，整体并发上限复用 imageInspector.maxConcurrency。模型未配置、被安全策略阻断或结构化结果无效时，收藏失败，已有条目不变。普通检索不调用任何模型。

检索使用中文二元字符与完整词的加权匹配，情景、情绪和风格权重高于画面描述。结果按得分和稳定 ID 排序，默认最多 5 项，最多可返回 25 项；空查询用于浏览。库容量大于 25 时用返回的 nextOffset 继续分页，或用关键词缩小范围。没有命中就返回空列表，不以随机表情充数。不确定含义时用结果中的 asset_id 调用 asset_media_view 看图。当前不做向量检索；它可以在相同资料之上添加，而无需改变收藏与发送协议。

主模型固定 prompt 只包含使用原则和工具说明，收藏清单、数量、时间不注入 system 前缀。变化的候选资料只在本轮工具结果出现，避免每次维护表情库都改变固定前缀。

## 管理与并发

- `sticker_collect`：传已有 asset_id，或 `sticker_qq_list` 返回的 qq_url。QQ 导入会验证地址仍在当前前 200 项收藏中；地址失效需重新列取，不使用可漂移的位置序号。
- 达到上限必须提供 replace_id、replace_revision 和理由。下载、分析成功后才在 SQLite 即时事务中检查容量、旧条目版本及锁定状态，并原子替换。替换产生新 ID；重复内容返回原条目，不删除替换目标。
- `sticker_update`：可修改用途资料和使用心得；纠正客观观察必须 reread=true，由视觉模型重新观察。更新失败不写入。
- `sticker_remove`：仅删除本地收藏，素材交回现有资产生命周期管理，不主动删除原图。
- 手动锁通过 owner 直接命令 `.sticker lock <表情ID>` / `.sticker unlock <表情ID>` 管理（私聊或群内 @ 机器人），不向模型暴露锁管理工具。锁定项不可修改、删除或替换，全锁定时无法新增到满额库。命令回显不进入模型历史。
- 修改、删除、替换及锁定操作使用 revision 乐观并发检查；发送次数不改变资料版本。
- 降低容量不会自动删库；超额状态拒绝净新增，允许一进一出替换或显式删除。
- 不必填满库，不每轮整理；仅有独特用途或明显更好的替代品时收藏，不仅因低频淘汰安慰、道歉等用途。

收藏通过外键保护 chat_files，回收器将所有收藏素材作为持久引用；手动删除被收藏的 asset 也会被拒绝。取消收藏只释放收藏引用，聊天会话引用仍独立有效。

## 识别与发送

接收端统一识别 mface、image.sub_type=1，以及携带商城表情标识的 image；普通图片不因 GIF 格式或 summary 文本被判为表情。商城 emojiId/packageId/key 随素材 sourceContext 保存，用于原生发送。

`sticker_send` 复用现有图片发送队列。普通图片表情发送 image.sub_type=1；有完整商城参数时发送 mface。Web 聊天使用本地素材展示。工具返回 queued 仅表示已排队，实际发送成功后才增加 useCount/lastUsedAtMs。发送失败不增加次数。

transcript 的 outbound_media_message 支持 mediaKind=emoji 和 toolName=sticker_send。Sessions 页仍用图片组件展示，并将动作标题标为“表情消息”；历史投影保留 emoji 语义。

## 运维与验证

配置示例见 global.example.yml。图片精读模型必须启用且路由到 supportsVision=true 的模型。表情库不在主模型前缀中暴露任何下载链接或商城 key，候选只包含 ID、素材引用和简短资料。

默认回归使用临时 dataDir、假视觉模型和假 OneBot 发送，不请求真实模型或操作 QQ 收藏。真实 NapCat 接收、商城发送与图片理解效果需要在隔离实例中联调；不要把模拟发送成功视为真实账号发送验证。
